换算链路（三步归一）

1) 平台报价 × 你的分组倍率          → 计费货币下的每百万 token 价
2) × 负载 token 数 / 1e6            → 每次请求的计费货币成本
3) × 充值杠杆（实付¥ ÷ 1 单位货币）  → 实付人民币 / 每次请求
   ÷ 官方基准的实付人民币            → 折扣%（100% = 跟官网直付一样贵）

分峰谷的站点：先按「高峰时段占比」把高峰价、空闲价线性混合，再进上面的链路。缓存命中留空时按未命中价计，因为多数站点只报一个输入价、不做缓存折扣——这正是 agent 负载最容易被隐形涨价的地方。

为什么看「每次请求」而不是「每百万 token」

同一份 agent 会话里，输入 token 的 99% 可能是缓存命中。站点 A 报 $0.018 平铺输入价，站点 B 报 $0.15 未命中价但缓存命中只收 $0.003：按每百万 token 看 A 便宜 8 倍，按真实请求看 A 反而更贵。所以默认负载单位就是「一次实测请求的 token 三件套」。

字段口径

  • 充值杠杆：实付 ¥ ÷ 到账计费货币。$1 到 $1 ≈ 7.1；¥1 到 $1 = 1（约 7 倍杠杆）。
  • 倍率：官方列表价 × 倍率 = 实际计费；留空取 1。
  • 折扣%：当前负载下实付人民币 ÷ 官方基准实付人民币，越小越便宜。
  • ×最优：同一模型内，该平台价格是最便宜那家的几倍。
  • 基准来源：官网价目表直接抄的标「官网价目表」；由平台公开的官方美元列表反推的标「推导」，会写进备注。
倍率、分组、峰谷规则都会变，节假日也可能调价——结论要带日期。有些站点把「官方价」按美元列表算（比人民币价目表低 6%~7%），比价前先问清基准。低价站常有合规/封号风险，价格优势要折进风险成本。
