# API 比价雷达

一个离线单文件 HTML：把各家中转站 / 官方 API 的 token 价目表，统一换算成
**「实付人民币 / 每次请求」**，然后按「按模型」或「按整体折扣」排序。

双击 `index.html` 就能用，不需要装任何东西、不联网、数据只写本机 localStorage。

## 为什么不能只比「每百万 token 报价」

同一份 agent 会话里，输入 token 的 99% 往往是**缓存命中**。站点 A 报 `$0.018` 平铺输入价，
站点 B 报 `$0.15` 未命中价但缓存命中只收 `$0.003`：

- 按每百万 token 看：A 便宜 8 倍
- 按一次真实请求看：A 反而贵 3.5 倍

所以工具默认用「一次实测请求的 token 三件套」当负载单位（默认 553 / 92,928 / 1,320，
来自真实账单），并且把「充值杠杆」和「分组倍率」显式建模。

## 三个数据入口

| 入口 | 位置 | 适用 |
|---|---|---|
| **给链接** | 「链接 / 账单 → ① 从链接读取」 | 价目页有内嵌 JSON、one-api 的 `ratio_config`、或服务端渲染的表格 |
| **截图 / 粘贴转写** | 「链接 / 账单 → ②」 | 页面要登录、纯 JS 渲染、价格只在截图里 |
| **表格粘贴** | 「导入 / 导出」 | 已经是文本表格（制表符 / Markdown / 逗号 / 分号） |
| **CSV 文件** | 三个入口都支持 | 选文件或直接拖进去：`.csv` `.tsv` `.txt` `.json` |

自动识别表头：平台、模型、输入、缓存、输出、倍率、备注；单元格支持
`$0.018 / $0.072`、`0.15/0.003/0.6`、`输入 $0.018 输出 $0.072`、`2元 / 8元`；
同一平台的多行可以只写一次平台名（下面的行留空即沿用）。

**CSV 文件**（`data/sample-prices-utf8.csv`、`data/sample-prices-gbk.csv` 可试）：

- 选择文件或直接把文件拖进文本框即可，读入后立刻解析预览
- 编码自动识别：带/不带 BOM 的 UTF-8、以及 Excel 在中文 Windows 下默认导出的 **GBK/GB18030**
- 引号字段里的逗号不会被切开（`"带,逗号的备注"`）、分号分隔的欧洲版 CSV 也认
- 表头 BOM 会被剥掉，不会把首列认错
- 只支持文本类文件；`.xlsx` 请在 Excel 里「另存为 CSV」再来

浏览器直接打开本地文件时会被跨域策略拦住，抓不到就用命令行（无跨域限制，内置 curl 兜底）：

```bash
node tools/fetch-prices.mjs fetch https://allrouter.cc/api/ratio_config --vendor allrouter.cc --group 0.4
node tools/fetch-prices.mjs fetch https://0-0.pro/models --vendor 0-0.pro --out 0-0.tsv
node tools/fetch-prices.mjs fetch <url> --json --out dataset.json    # 直接产出可导入的 JSON
```

实测：`allrouter.cc/api/ratio_config` 能直接抓出分峰谷的 `billing_expr`（`p*0.3+cr*0.006+c*1.2`），
`0-0.pro/models` 能抓出页面里的价格 JSON；`api.zeekai.cc` 是登录后 SPA，抓不到 → 走截图/转写。

## 账单明细反推真实单价

「链接 / 账单 → ③」把明细贴进来（CSV / TSV / JSON，需要 模型 · 输入 · 缓存 · 输出 · 扣费，可选 时间 / 档位）。
工具用最小二乘反解三档真实单价，并给出判定：

- 「命中 ÷ 输入」≈ 100% → 这家的缓存**不打折**（缓存 token 按输入价收）
- 明显小于 20% → 缓存确实打折
- 有「档位」列时，会按档位分别求解，验证峰谷是否真的价差

示例（`data/sample-bill.csv`，按 0.06 / 0.0012 / 0.24 生成）：

```bash
node tools/fetch-prices.mjs bill data/sample-bill.csv
# 全部  6  0.0600  0.0012  0.2400  2.0%  2.7e-9
```

反解得和真实值完全一致（残差 1e-9 量级），说明这套单价能解释全部账单。

## 换算链路

```
平台报价 × 分组倍率            → 计费货币下的每百万 token 价
× 负载 token 数 / 1e6          → 每次请求的计费货币成本
× 充值杠杆（实付¥ ÷ 1 单位货币）→ 实付人民币 / 每次请求
÷ 官方基准的实付人民币          → 折扣%（100% = 跟官网直付一样贵）
```

- **充值杠杆**：$1 到账 $1 ≈ 7.1；¥1 到账 $1 = 1（约 7 倍杠杆）
- **峰谷**：分档站点按「高峰时段占比」把高峰价、空闲价线性混合
- **缓存列留空** = 按未命中价计费（多数站点只有一档输入价）

## 内置示例数据（2026-11-11 实测，deepseek-v4.1-flash）

| 平台 | 报价口径 | 实付 ¥/请求 | 折扣 |
|---|---|---|---|
| api.zeekai.cc | ¥1→$1，倍率 0.15x | 0.000173 | 1.4% |
| allrouter.cc | $1=10 积分，倍率 0.4x，分峰谷 | 0.005243 | 42.6% |
| DeepSeek 官方 | 人民币价目表，分峰谷 | 0.012306 | 100% |
| 0-0.pro | $1→$1，平铺价无缓存折扣 | 0.012622 | 102.6% |

（峰值占比 0.6。官方与分档平台是同步切换的，所以**折扣率不随峰谷变化**，但绝对金额差一倍：
全空闲档时 allrouter 0.003277、官方 0.007692、zeekai 0.000173 不变——zeekai 与 0-0.pro 不分峰谷，
所以在空闲时段相对更贵、在高峰时段相对更便宜。）

结论见「口径说明」页；数据可整体导出/导入（`data/dataset-2026-11-11.json`）。

## 已知限制

- 倍率、分组、峰谷规则会变，节假日也可能调价 —— 结论要带日期。
- 有的站点把「官方价」按美元列表算（比人民币价目表低 6%~7%），比价前先问清基准；
  工具里每个基准价都带「来源」字段（官网价目表 / 推导）。
- 反推单价需要足够的样本多样性（至少 3 组差异明显的 token 组合），否则列退化会自动降级为两参数模型。
